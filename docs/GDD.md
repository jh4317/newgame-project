## 1. 개요

쿼터뷰에 가까운 3인칭 탑뷰 시점의 고속 3D 액션 게임이다. 패링, 슬라이딩, 벽 타기를 이어 붙여 움직임 자체로 싸우는 재미가 핵심이다.

| 항목 | 내용 |
| --- | --- |
| 가제 | 미정 (미정 사항 참고) |
| 한 줄 소개 | 먹을 다루는 검사가 멈추지 않고 미끄러지고, 벽을 타고, 적을 먹으로 물들여 베어 내는 탑뷰 액션 |
| 장르 | 3인칭 탑뷰 3D 액션 (아레나 전투 중심). 탑뷰가 어렵다면 숄더뷰 3인칭으로 전환(4.4) |
| 플랫폼 | PC (Windows), Steam 출시 목표 |
| 개발 규모 | 1인 개발, Godot 4.7.2 |
| 대상 플레이어 | 하이 스피드 액션과 스타일 평가를 즐기는 코어 액션 게이머 |
| 핵심 재미 | 빠른 이동, 정확한 타이밍의 패링, 공격적으로 플레이할수록 보상받는 구조 |

**레퍼런스 활용 원칙:** ULTRAKILL은 전투 감각의 기준점으로만 쓴다. 패링·슬라이딩·벽 이용 이동이라는 메커니즘의 방향은 참고하되, 1인칭 FPS를 탑뷰로 옮기면서 생기는 차이에 맞게 새로 설계한다. 캐릭터, 세계관, 적, 무기, 레벨, 아트, 이름은 모두 오리지널로 만든다.

## 2. 디자인 필러

모든 기능은 아래 네 가지 원칙 중 하나 이상을 강화해야 들어간다.

1. **멈추면 죽는다:** 가만히 있는 것보다 움직이는 것이 항상 안전하다. 이동 기술 자체가 회피이자 공격 수단이다.
2. **방어는 공격이다:** 막기만 하는 방어는 없다. 패링에 성공하면 반드시 대미지나 회복으로 보상한다.
3. **한눈에 읽힌다:** 탑뷰에서는 적의 공격 예고, 패링 가능 여부, 벽 타기 가능 지형이 색과 형태만으로 구분돼야 한다.
4. **짧고 짙게:** 아레나 하나는 2~4분. 1인 개발 규모에 맞게 콘텐츠 양보다 반복 플레이의 깊이를 우선한다.

## 3. 핵심 전투 시스템

전투는 패링, 슬라이딩, 벽 타기 세 가지 동작을 끊김 없이 이어 쓰는 것을 중심으로 설계한다. 1인칭 기준의 레퍼런스와 달리 탑뷰에서는 높이와 조준이 잘 보이지 않으므로, 각 동작을 평면 위에서 읽히도록 바꾼다. 아래 수치는 모두 프로토타입에서 조정할 **초기값**이다.

### 3.1 패링

패링 버튼을 누르면 조준 방향으로 짧은 판정이 열린다. 이 안에 들어온 패링 가능 공격을 되받아친다.

- **투사체 패링:** 투사체를 조준 방향으로 되돌려 보낸다. 속도와 대미지가 커지고, 조준 보정으로 가까운 적을 향한다.
- **근접 패링:** 적의 근접 공격을 튀겨내 적을 경직시킨다. 경직 중인 적은 추가 대미지를 받는다.
- **성공 보상:** 히트스톱(잠깐 멈추는 연출), 임팩트 프레임(3.5), 체력 회복, 스타일 점수.
- **실패 부담:** 헛치면 짧은 후딜레이가 있어 난발할 수 없다.
- **가독성:** 패링 가능한 공격은 흑백 이펙트 안에서 흰색 섬광으로 예고한다. 패링 불가 공격은 공격 직전에 붉은색 표식을 이펙트로 띄운다. 붉은색은 이 용도로만 쓰는 유일한 예외 색이다.

### 3.2 슬라이딩

달리는 중 슬라이드 버튼을 누르고 있는 동안 감속 없이 미끄러진다. 최고 속도를 유지하는 주된 수단이다.

- 달리기보다 빠르고, 방향 전환은 느리다. 빠르게 방향을 바꾸려면 슬라이드를 끊어야 한다.
- 자세가 낮아져 ‘높은 공격’(가로 레이저, 휘두르기)을 피한다. 탑뷰에서는 높은 공격을 바닥에서 떠 있는 표시 라인과 그림자로 구분한다.
- 슬라이드 중 점프하면 속도를 유지한 채 멀리 뛴다(슬라이드 점프). 넓은 아레나를 가로지르는 기본 기술이다.
- 슬라이드 중에도 사격과 패링은 가능하다.

### 3.3 벽 타기

공중에서 벽에 닿으면 벽에 붙어 천천히 미끄러져 내려간다. 이 상태에서 점프하면 벽 반대쪽 위로 튀어 오른다.

- 벽 점프는 스태미나 1칸을 쓴다(3.6). 스태미나는 바닥에 있을 때만 회복된다.
- 마주본 두 벽 사이를 번갈아 차며 위층 발판으로 올라간다. 아레나의 고저차를 활용하는 핵심 수단이다.
- 탈 수 있는 벽은 전용 재질(예: 줄무늬 패널)로 표시한다.
- **탑뷰 문제와 해결:** 벽이 캐릭터를 가릴 수 있다. 카메라와 캐릭터 사이의 벽은 반투명 처리하고, 캐릭터 실루엣을 표시한다. 바닥의 그림자로 현재 높이를 알려 준다.

### 3.5 임팩트 프레임

임팩트 프레임은 결정적인 타격 순간을 짧은 흑백 정지 화면으로 강조하는 **필수** 연출이다.

- **발동:** 패링 성공, 보스에게 큰 타격, 아레나 마지막 적 처치, 보스 처치.
- **표현:** 화면을 흑과 백 두 색의 고대비 실루엣으로 바꾼다(반전 포함 가능). 흰 부분은 블룸으로 번지게 한다.
- **길이:** 일반은 2프레임(약 0.03초). 보스 처치 같은 큰 순간은 히트스톱과 합쳐 최대 0.2초.
- **남발 방지:** 같은 종류는 1초에 한 번만 발동한다. 일반 처치에는 쓰지 않는다.
- **접근성:** 설정에서 끄거나 약하게 할 수 있다(8.2 화면 섬광 줄이기와 연동).

### 3.6 대시·스태미나·버니합

대시와 버니합은 고속 이동을 이어 가는 보조 수단이다. 대시는 벽 점프와 같은 스태미나를 나눠 쓴다.

- **대시:** 입력 방향(없으면 바라보는 방향)으로 0.15초 동안 30 m/s로 직선 이동한다(약 4.5 m). 지상과 공중 모두 가능하고, 그동안 중력을 받지 않는다. 끝나면 들어올 때 속도(최소 달리기 속도)를 유지한다. 대시 중 점프하면 즉시 끊고 점프로 이어진다.
- **스태미나:** 3칸. 벽 점프와 대시가 1칸씩 쓴다. 바닥에 있을 때만 0.5초에 1칸씩 회복한다. 공중에서 대시를 쓰면 그만큼 벽 점프가 줄어드는 선택이 생긴다.
- **버니합:** 착지 후 0.12초 안에 점프하면 지면 마찰 없이 속도를 유지하고, 1회당 1 m/s를 더한다(최고 28 m/s, 10 m/s 이상으로 움직일 때만). 점프 입력 버퍼(0.12초) 덕분에 착지 직전에 눌러도 성공한다. 타이밍을 놓치면 연속 기록이 끊긴다.

### 3.7 첫 무기: 검기 검

검을 한 번 휘두를 때마다 근접 베기와 검기가 함께 나간다. 가까이 붙을수록 강하고, 멀어도 검기로 견제할 수 있다.

- **근접 베기:** 조준 방향 120°, 반경 2.8 m. 적 체력 2칸. 근접으로 처치하면 체력 20 회복(5.1).
- **검기:** 초승달 모양의 흰 파동이 35 m/s로 25 m 날아간다. 적을 관통하며 체력 1칸. 조준 방향 15° 안의 적(높이 차 포함)을 향해 보정된다. 같은 휘두르기의 근접에 맞은 적은 검기에 다시 맞지 않는다.
- **3타 콤보:** 0.28초 간격, 0.6초 안에 이어 휘두르면 콤보가 이어진다. 3타는 마무리 베기로 범위 1.25배, 근접 체력 3칸, 검기 1.5배. 버튼을 누르고 있으면 계속 휘두른다.
- **타격감:** 근접 적중은 히트스톱 0.045초와 카메라 흔들림, 검기 적중은 더 가볍게.

### 3.8 먹 시스템

주인공은 먹을 다루는 검사다. 모든 공격이 적에게 먹을 묻히고, 충분히 쌓인 먹을 근접 베기로 터뜨려 큰 피해를 준다. 멀리서 묻히고(검기·반사탄) 가까이 붙어 터뜨리는 흐름이 ‘거리를 좁혀라’는 원칙(2장, 5.1)을 강화한다.

| 공격 | 쌓이는 먹 (최대 100) |
| --- | --- |
| 근접 베기 | 25 |
| 3타 마무리 베기 | 35 |
| 검기 | 20 |
| 3타 검기 | 30 |
| 반사탄 | 30 |
| 패링 성공 | 즉시 100 (탄을 쏜 적의 먹방울 5칸이 가득 찬다) |

- **먹 폭발:** 먹이 60 이상일 때 근접 베기를 맞히면 먹을 전부 터뜨려 추가 피해 40~80을 준다(쌓인 양에 비례, 적 체력 2~4칸). 터뜨린 뒤 이번 베기의 먹이 새로 묻는다. 검기와 반사탄은 터뜨리지 못하고 묻히기만 한다.
- **마름:** 3초 동안 먹이 새로 묻지 않으면 초당 20씩 마른다.
- **표시:** 적 머리 위 먹방울 5칸. 쌓일수록 몸이 먹빛으로 물들고 먹물이 떨어지며, 몸 주변에서 검은 기운이 소용돌이치며 피어오른다(쌓인 양에 비례해 더 크고 빠르게). 기준치 이상에서는 검은 기운 사이로 흰 불티가 흩날린다. 60 이상이면 발밑에 흰 고리가 맥동해 지금 베라고 알려 준다. 먹이 묻을 때마다 잔향이 남는다: 적의 검은 실루엣이 메아리처럼 2~3겹 퍼지고, 먹 고리가 퍼지며, 주변 먹방울이 몸으로 빨려 들고, 새로 찬 먹방울 칸이 톡 튄다. 많이 묻을수록 크고, 기준치를 넘는 순간에는 흰 잔향이 더해진다.
- **연출:** 검은 먹방울이 사방으로 튀고 바닥에 큰 먹 자국, 섬광, ‘먹 폭발’ 문구와 추가 피해 숫자, 화면 붓터치·줌 펀치·임팩트 프레임.

**먹 끌어당김:** 먹이 가득(100) 찬 적에게 반사탄을 맞히면, 그 적을 중심으로 14 m 안의 다른 적을 2.6 m 거리까지 끌어당긴다. 끌려온 적에게도 먹 30이 묻는다. 동시에 플레이어 체력 25 회복, 먹 스타일 300점. 패링이 쏜 적의 먹을 즉시 가득 채우므로, 되받아친 탄이 그 적에게 돌아가면 자연스럽게 발동한다 → 모인 적을 근접으로 한꺼번에 터뜨리는 흐름. 연출: 검은 고리가 오므라들고 적마다 먹 사슬이 이어졌다 끊기며 ‘먹 끌어당김’ 문구와 회복 숫자가 뜬다.

## 4. 이동·카메라·조작

높은 이동 속도가 기본이므로, 카메라는 플레이어가 향하는 쪽을 먼저 보여 주고 조작은 입력 즉시 반응해야 한다.

### 4.1 카메라

- 내려다보는 각도 약 55°의 고정 사선 탑뷰. 회전은 기본적으로 막고, 방향 감각을 일정하게 유지한다.
- **선행 시점:** 카메라가 이동 방향과 조준 방향으로 약간 앞서 나간다. 고속일수록 더 멀리 보여 준다.
- **속도감 연출:** 슬라이드와 고속 이동 중에는 시야를 살짝 넓히고, 속도선과 카메라 흔들림을 넣는다.
- 캐릭터를 가리는 벽과 천장은 반투명 처리한다(3.3 참고).

### 4.2 조준

- 키보드·마우스: 마우스 커서 위치를 향해 조준한다(트윈 스틱 방식).
- 게임패드: 오른쪽 스틱으로 조준하고, 약한 조준 보정을 넣는다.
- 높이차가 있는 적은 자동으로 수직 조준한다. 플레이어는 평면 방향만 신경 쓴다.

| 대시 | E | X |

### 4.4 대안 시점: 숄더뷰 3인칭

탑뷰에서 높이 판단이나 벽 타기가 답답하면, Warframe·Helldivers 2처럼 캐릭터 어깨 뒤에서 보는 3인칭으로 바꾼다. 결정은 1단계(이동 프로토타입) 관문에서 한다.

- **바뀌는 것:** 마우스로 카메라를 돌리고 화면 중앙 조준점으로 조준한다. 벽 반투명 처리 대신 카메라 충돌 처리가 필요하다.
- **유지되는 것:** 패링·슬라이딩·벽 타기 규칙과 수치, 적 설계, 임팩트 프레임.
- **장점:** 높이와 벽이 잘 보여 벽 타기가 쉬워지고, 고속 이동의 속도감이 커진다.
- **단점:** 뒤쪽 적이 안 보여 화면 가장자리 공격 경고가 필요하다.
- **대비:** 1단계에서 카메라 컨트롤러를 교체 가능한 구조로 만들어 두 시점을 모두 시험한다.

## 5. 전투 루프와 스타일 평가

어색하게 숨어서 버티면 오히려 불리하고, 빠르고 공격적으로 플레이해야 체력이 회복되는 구조다.

**핵심 전투 루프** (원본 문서의 그림): 이동(슬라이드·벽 점프로 접근) → 공격(사격과 근접 공격) → **패링**(되받아쳐 큰 피해) → 보상(체력 회복·스타일 점수) → 다시 이동. 멈추면 보상이 끊긴다.

패링이 루프에서 가장 큰 보상을 주는 단계다. 루프가 끊기면 회복도 점수도 멈춘다.

### 5.1 체력 회복

- 회복 아이템은 두지 않는다. 근거리 처치와 패링 성공으로만 회복한다.
- 피격 대미지 일부는 ‘회복 가능 체력’으로 남는다. 일정 시간 안에 반격하면 되찾는다.
- 멀리서 사격만 하면 회복량이 적다. 거리를 좁히는 이동 기술이 생존과 직결된다.

### 5.2 스타일 평가

- 처치, 패링, 공중 처치, 슬라이드 중 처치 같은 행동마다 점수를 준다.
- 같은 행동을 반복하면 점수가 줄어든다. 다양한 기술을 섞도록 유도한다.
- 점수는 시간이 지나면 서서히 줄고, 피격당하면 크게 깎인다.
- 등급은 6단계 ‘먹 스타일’: 점 → 획 → 필 → 묵 → 농묵 → 일필휘지 (등급당 300점). 높은 등급일수록 빨리 줄고(초당 20 + 등급당 14), 피격하면 300점(한 등급)이 깎인다. 최근 4개 행동 안에서 반복하면 점수가 1/2, 1/3로 줄어든다.
- 아레나가 끝나면 클리어 시간, 최고 등급, 피격 횟수로 종합 평가를 낸다.

| 행동 | 점수 (초기값) |
| --- | --- |
| 먹 끌어당김 | 300 |
| 먹 폭발 | 200 |
| 패링 | 120 |
| 처치 | 100 (공중 ×1.5, 슬라이드 ×1.3) |
| 반사탄 적중 | 80 |
| 마무리 베기 | 70 |
| 베기 | 40 |
| 큰 검기 / 검기 | 30 / 20 |

## 6. 적과 보스

적은 플레이어가 패링·슬라이딩·벽 타기 중 하나를 쓰게 만드는 역할로 설계한다. 하나의 아레나에는 서로 다른 대응을 요구하는 적을 섞는다.

### 6.1 설계 원칙

- 모든 공격은 발사 전 예고 동작을 보여 준다. 고속 이동 중에도 읽힐 수 있도록 0.3초 이상을 기본으로 한다.
- 적의 실루엣은 탑뷰에서 멀리서도 구분돼야 한다. 크기와 형태가 유형별로 확실히 달라야 한다.
- 패링 불가 공격의 붉은 예고 표식은 모든 적과 보스에 똑같이 적용한다. 붉은색이 보이면 패링하지 말고 피해야 한다. 패링 불가 공격은 중급 이상 적부터 쓰고, 하급 적은 패링 가능한 공격만 쓴다.

### 6.2 적 유형(초안)

| 유형 | 역할 | 주요 공격 | 플레이어에게 요구하는 대응 |
| --- | --- | --- | --- |
| 돌격형 | 근접 압박 | 빠른 돌진 베기 | 근접 패링 또는 슬라이드로 빠져나가기 |
| 사격형 | 원거리 견제 | 패링 가능한 탄 (중급은 붉은 탄을 섞음) | 탄을 되받아쳐 역이용 |
| 포탑형 | 구역 봉쇄 | 가로 레이저 | 슬라이드로 밑을 통과 |
| 공중형 | 고지대 점령 | 위에서 내리찍기 | 벽 점프로 올라가 요격 |
| 방패형 | 정면 방어 | 방패 밀치기 | 슬라이드로 뒤로 돌아 치기 |

### 6.3 보스

- 스테이지마다 보스 1체. 체력에 따라 2~3페이즈로 패턴이 바뀐다.
- 페이즈마다 세 핵심 동작 중 하나를 주연으로 삼는다(예: 1페이즈 패링, 2페이즈 벽 타기, 3페이즈 모두 섞기).
- 보스 디자인과 세계관 설정은 미정이다.

## 7. 레벨 디자인

레벨은 ‘이동 구간 → 아레나 전투’를 짧게 반복하는 구조다. 고속 이동이 기본이므로 공간은 넓고, 멈추지 않고 흐르듯 지날 수 있게 만든다.

### 7.1 아레나 구조

- 넓이는 슬라이드 속도 기준 가로지르는 데 3~4초 정도로 잡는다(약 60~80 m).
- 바닥 층과 위층 발판 2~3단으로 고저차를 둔다. 위층은 벽 점프로만 올라갈 수 있다.
- 기둥과 마주본 벽 쌍을 배치해 벽 점프 경로를 여러 개 만든다.
- 길고 곧은 통로는 슬라이드 구간이다. 포탑형 적의 레이저와 조합한다.
- 적은 2~4개 웨이브로 나눠 등장한다. 마지막 웨이브를 처치하면 출구가 열린다.

### 7.2 스테이지 구성

- 출시 버전 목표: 3개 스테이지, 스테이지마다 아레나 4개 + 보스 1체.
- 스테이지 1: 패링과 슬라이딩을 가르친다. 고저차는 최소한으로.
- 스테이지 2: 벽 타기와 수직 전투를 중심으로.
- 스테이지 3: 세 동작을 모두 섞는 고난도.
- 튜토리얼은 별도 화면 없이 첫 아레나 안에서 한 동작씩 가르친다.

### 7.3 탑뷰 고려 사항

- 카메라 각도에서 높은 벽이 시야를 가리지 않게, 카메라 쪽 벽은 낮게 쓰거나 반투명 처리한다.
- 위층 발판의 가장자리는 밝은 윤곽선으로 표시해 높이를 읽게 한다.

## 8. 진행·UI·아트·사운드

화면은 ‘거친 로우폴리 세계 위에 눈부신 흑백 이펙트’라는 대비로 정의한다. 세계는 단순하게, 전투 이펙트는 화려하게 만든다.

### 8.1 진행·보상

- 스테이지를 클리어하면 다음 스테이지가 열린다. 아레나별 최고 등급과 클리어 시간을 기록한다.
- 무기는 스테이지 진행에 따라 1개씩 해금한다(출시 목표 3~4종). 능력치를 올리는 성장 요소는 두지 않는다.
- 높은 등급을 받으면 외형이나 도전 모드 같은 보상을 준다.
- 저장은 아레나 단위 체크포인트로 한다. 죽으면 현재 아레나를 즉시 다시 시작한다.

### 8.2 UI/UX

- HUD는 최소한으로: 체력(회복 가능 체력 포함), 스태미나(벽 점프·대시 공용), 현재 무기, 스타일 등급.
- 스태미나는 캐릭터 발밑에 점 3개로 표시한다. 고속 이동 중에 화면 구석을 볼 필요가 없게 한다.
- 죽은 뒤 재시작까지 1초 이내. 로딩 화면으로 속도감을 끊지 않는다.
- 설정: 키 바꾸기, 카메라 흔들림 세기, 블룸 세기, 화면 섬광 줄이기(접근성).

### 8.3 아트 방향

- **세계와 캐릭터:** 로우폴리 스타일. 폴리곤 수를 적게 쓰고, 저해상도 텍스처를 필터 없이 입힌다. 레퍼런스는 ULTRAKILL, MOUTHWASHING의 로우폴리 톤이다.
- **이펙트:** 로우폴리가 아닌 화려한 이펙트. 블룸을 강하게 적용하고, 흑백 위주의 고대비 색으로 빛난다. 흑백은 이펙트에만 쓰고, 세계와 캐릭터는 색을 유지한다.
- 임팩트 프레임(3.5)은 이펙트 연출의 중심이다. 결정적인 순간에 화면 전체를 잠깐 흑백 실루엣으로 바꾼다.
- 총연, 탄흔, 폭발은 흰색 발광 + 검은 연기로 대비를 만든다. 주인공이 다루는 먹(검정)과 검기·섬광(흰색)이 이 대비의 중심이다.
- 흑백 이펙트의 유일한 예외는 붉은색이다. 패링 불가 공격의 직전 예고에만 써서, 흑백 화면 속에서 한눈에 띄게 한다(3.1).

### 8.4 사운드 방향

- 빠른 템포의 전자음악 또는 인더스트리얼 계열. 스타일 등급이 오르면 음악 레이어를 더한다.
- 패링, 슬라이드 시작, 벽 점프는 각각 고유한 짧은 소리를 주어 화면을 보지 않아도 알 수 있게 한다.
- 음악과 효과음은 직접 제작하거나 상용 라이선스 에셋을 쓴다.

## 9. 기술 사양

Godot 4.7.2와 GDScript로 개발한다. 현재 프로젝트의 Forward+ 렌더러와 Jolt 물리 설정을 그대로 쓴다. Forward+는 블룸(Glow)과 후처리 효과를 제대로 지원하므로 이펙트 방향과 맞는다.

| 항목 | 결정 |
| --- | --- |
| 엔진 | Godot 4.7.2 (Steam판) |
| 언어 | GDScript (.NET SDK가 없어 C#은 쓰지 않음) |
| 렌더러 | Forward+, Direct3D 12 |
| 물리 | Jolt Physics, 물리 틱 120Hz (고속 이동 시 벽 통과 방지) |
| 목표 성능 | 1080p에서 144fps, 최소 60fps |
| 플랫폼 | Windows, Steam (내보내기 템플릿 설치 필요) |
| 버전 관리 | git + GitHub 비공개 저장소 |

### 9.1 화면 표현 구현

- **로우폴리 룩:** 텍스처 필터를 Nearest로 두고, 3D 렌더 해상도를 낮춰(`scaling_3d_scale` 약 0.5) 거친 느낌을 낸다. 정점 흔들림 같은 레트로 셰이더는 선택 사항이다.
- **블룸:** WorldEnvironment의 Glow를 켜고, 이펙트는 밝기 1을 넘는 HDR 발광 재질로 만든다. 발광하는 것만 빛나도록 임계값을 둔다.
- **흑백 연출:** 화면 전체 반전·채도 제거는 전체 화면 셰이더(CanvasLayer 위 ColorRect)로 처리한다. 임팩트 프레임도 같은 셰이더로 만든다. 밝기 임계값으로 화면을 흑과 백으로 나누고, 그동안 `Engine.time_scale`을 0에 가깝게 둔다.
- 낮은 해상도 렌더링에서 블룸이 뭉개지지 않는지 프로토타입에서 확인해야 한다.

### 9.2 코드 구조(초안)

- **플레이어:** CharacterBody3D + 상태 머신(서기, 달리기, 슬라이드, 공중, 벽 붙기, 패링). 이동은 직접 계산해 조작감을 통제한다.
- **투사체:** 오브젝트 풀링. 빠른 탄은 레이캐스트로 매 프레임 충돌을 검사해 통과를 막는다. 패링 가능 여부는 투사체 속성으로 둔다.
- **적:** 공통 기반 스크립트 + 유형별 상태 머신. 길 찾기는 NavigationAgent3D.
- **오토로드:** GameManager(진행·저장), StyleMeter(스타일 점수), HitStop(히트스톱을 위한 짧은 `Engine.time_scale` 조절).
- **폴더:** `scenes/`, `scripts/player/`, `scripts/enemies/`, `scripts/systems/`, `assets/models/`, `assets/vfx/`, `assets/audio/`.
- 현재 프로젝트에 있는 2D 바운스 프로토타입(`scenes/main.tscn`, `scripts/*.gd`)은 본 개발을 시작할 때 정리하거나 별도 폴더로 옮긴다.

- [ ] 개발 시작일과 출시 목표일
- [ ] 아트·사운드 제작 방식: 직접 제작 비중과 구매할 에셋
